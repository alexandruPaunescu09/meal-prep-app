# UX review — 2026-10-17

Read-only review of the admin app and the customer portal. Three parallel explore passes covered: admin catalog + shell, admin planning + ops, customer portal + intake. Line numbers refer to `main` at `de44aa4`. Severity: **H** = a daily user feels it / risks data, **M** = noticeable friction, **L** = polish.

Spot-verified against code: recipe-form delete-then-insert, prep "Generate" wiping completed tasks, swallowed photo-upload failure, portal status save without rollback, Duplicate plan not copying targets — all confirmed.

---

## 1. Cross-cutting themes

1. **No shared modal primitive.** Every modal is a copy-pasted `fixed inset-0` div: no `role="dialog"`/`aria-modal`, no Escape, no focus trap, no autofocus, no unsaved-changes guard, z-index 40 vs 50, backdrop-click behaviour inconsistent (only the review modal closes on backdrop). Biggest risk: `components/recipe-form.tsx` — one accidental Cancel loses a whole recipe.
2. **`alert()` / `confirm()` everywhere, errors ignored.** 12+ call sites (ingredients, recipes, categories, meal plans, clients, containers, prep, every grid rollback). Delete/clone/reorder results are often unchecked. `import-client.tsx:808-844` already has an in-page confirm dialog; there is no toast system.
3. **Silent data-integrity failures:**
   - `components/recipe-form.tsx:134-151` — `recipe_ingredients` delete result unchecked, then insert; failed insert leaves recipe with no ingredients.
   - `app/(authenticated)/prep/prep-client.tsx:93-98` — Generate deletes all tasks for the week (including completed) without confirmation or error checks.
   - `app/(authenticated)/meal-plans/[id]/meal-plan-grid.tsx:1808-1845` — Duplicate: plan + entries not atomic (orphan plan on failure), targets (`calorie_target`, `protein_per_kg`, `fat_per_kg`) not copied, default week = next Monday from *today* instead of source week + 7.
   - `components/delivery-form.tsx:97-149` — delivery + items not atomic; retry can duplicate.
4. **Formatting / locale drift.** Raw ISO weeks (`Week of 2026-10-19`), mixed en-US / en-GB / device-locale dates, lei via `toFixed(2|4)` with dot decimal and no unit (`0.0123 lei` per g? ml?), all-English UI for a Romanian business, `<html lang="en">`. `toISOString()` Monday maths can be a day off in UTC+2/3 (`meal-plans-client.tsx:160-163`, `prep-client.tsx:31`, `meal-plan-grid.tsx:1794`); `new Date("YYYY-MM-DD")` parses as UTC in the portal (`plans/page.tsx:92-98`, `plans/[id]/page.tsx:73`).
5. **Accessibility basics.** Icon-only buttons without `aria-label`; ~28px targets (`p-1.5` + 14px icon); grid drag handle and remove-X hover-only (unusable on touch); no dnd-kit `KeyboardSensor`; labels not tied to inputs (login, intake); no `prefers-reduced-motion`; no iOS safe-area padding on bottom tabs; color-only status in a few places.

## 2. Suggested implementation order

1. **Foundations:** shared `Modal`, `ConfirmDialog`, `useToast`; `formatLei` / `formatDate` / `formatWeek` (ro-RO, local-date safe). Replace every `alert()`/`confirm()`.
2. **Integrity:** atomic recipe save, plan duplicate, delivery (RPCs); prep generate preserves completed tasks; portal status rollback; stop swallowing photo-upload errors.
3. **Customer quick wins:** one-tap Eaten on meal cards, sync-status chip, "Review sent" toast, first-run Today state, `loading.tsx`/`error.tsx` under `(portal)`.
4. **Admin workflow:** "New week from last week", plans list grouped by week, SlotPicker multi-add, undo on entry delete, cross-links (client ↔ plans ↔ containers ↔ reviews), search/sort on ingredients + recipes.
5. **Accessibility sweep:** aria-labels, 44px targets, visible drag/remove on touch, KeyboardSensor, reduced motion, safe-area padding.

### Bigger ideas
- **Week-centric home / "New week" wizard:** week view with client rows, status chips, kcal-vs-target badges, revenue; one action clones last week for every client (entries + targets), then a checklist: plans built → shopping → cooking → prep → deliveries.
- **Actionable dashboard:** "needs attention" (unread reviews, ingredients with no price/nutrition, recipes with no container, stale prices, this week's plan/prep status) and quick actions that open forms directly (`?new=1`).
- **Recipe builder 2.0:** two-pane (picker | live cost/macros/margin), multi-add, per-row cost, selling price/margin target, atomic save + draft autosave.
- **Ingredient list inline editing + bulk actions:** editable price/quantity cells, multi-select for category change/delete, "prices updated N days ago" linking to receipt import.
- **Delivery & container ledger:** per-client delivery history, "log return" shortcuts, outstanding-balance trend.
- **Customer daily progress:** kcal vs target, macro ring, meals-logged streak.
- **Customer onboarding:** intake confirmation → "what happens next" timeline → install prompt (Android `beforeinstallprompt` + iOS hint) → notification opt-in when first plan is published.
- **Proper offline model:** IndexedDB queue, per-item pending/failed/retry, SW background sync, photo retry separate from review text.
- **Review lifecycle:** edit/delete, photo replace/remove with progress, "How was it?" nudge after marking eaten, recent reviews on profile.
